# Redis 底层结构概览（仅保留当前仍在使用的结构）

Redis 对外提供的是抽象数据类型（string、list、hash、set、zset、stream 等），
对内通过多种底层结构实现，并通过 `encoding` 字段进行区分。实际的值对象可以理解为：

- **type**：抽象类型（string/list/hash/set/zset/stream/...）
- **encoding**：底层结构类型（raw、int、hashtable、intset、quicklist、listpack、skiplist 等）
- **ptr**：指向底层结构的指针

下面只介绍 **当前仍在使用的主要底层结构**，以及它们与抽象类型的关系。

---

## 一、SDS（Simple Dynamic String）

SDS 是 Redis 自己实现的动态字符串，是绝大多数字符串相关数据的基础。

- **用途**：
  - 所有 key 一般都是 SDS
  - string 类型的值常用 SDS 存储
  - hash、zset 等结构里的字段名、成员名本质也都是 SDS
- **特性**：
  - 额外存储长度信息，`O(1)` 获取长度
  - 自动扩容，减少缓冲区溢出的风险
  - 预分配与空间回收机制，降低频繁分配的开销

**与抽象类型的关系：**

- string：使用 SDS 或整数（int）存储
- hash、zset 等：field/member 也依赖 SDS 存储具体内容

---

## 二、整数编码（int）

当一个 string 的内容是可以用 long 表示的整数，并且在范围内时，Redis 会用整数编码存储，而不是 SDS。

- **特点**：
  - 节省内存
  - 对 `INCR`、`DECR` 等操作更高效

**与抽象类型的关系：**

- string：可以是 **int 编码** 或 **SDS 编码**

---

## 三、哈希表（dict / hashtable）

Redis 内部大量使用的通用结构，用于实现 keyspace、hash 类型的大结构、set/zset 的一部分等。

- **实现要点**：
  - 使用数组 + 链表解决冲突（具体实现随版本可能细节不同）
  - 支持渐进式 rehash，避免一次性扩容导致阻塞

**与抽象类型的关系：**

- hash：
  - 当元素数量较大或 field/value 较长时，使用 **hashtable** 编码
- set：
  - 当元素不是纯整数，或数量超过阈值时，使用 **hashtable** 编码
- zset：
  - 大型有序集合中，用 **dict** 记录 member -> score 映射

---

## 四、listpack（紧凑列表）

listpack 是一种顺序存储的小块数据结构，设计用于替代旧的压缩列表（ziplist），更高效且更安全。

- **特点**：
  - 连续内存，缓存友好
  - 为小数据量场景提供紧凑存储

**与抽象类型的关系：**

- hash：小型 hash 可以使用 **listpack** 编码
- zset：小型 zset 可以使用 **listpack** 编码
- stream：每个节点中会使用 listpack 存储多条记录

---

## 五、intset（整数集合）

intset 是专门为只包含整数的小型集合设计的紧凑结构。

- **特点**：
  - 内部使用有序的整数数组
  - 支持多种整数宽度（int16、int32、int64），可以在需要时升级

**与抽象类型的关系：**

- set：
  - 当集合所有元素都是整数，并且集合较小时，使用 **intset** 编码

当元素不再是纯整数或数量超过阈值时，会自动升级为 hashtable 编码。

---

## 六、quicklist（双向链表 + 压缩块）

quicklist 是 Redis 针对 list 类型定制的结构，将双向链表与紧凑块（如 listpack）结合到一起。

- **结构概览**：
  - 外层是双向链表，每个节点是一个小块（通常是 ziplist/listpack）
  - 既保留了链表前后插入的方便，又利用紧凑块优化内存和局部性

**与抽象类型的关系：**

- list：
  - 统一使用 **quicklist** 编码（内部再组合使用紧凑块）

---

## 七、skiplist（跳表）

skiplist 是一种有序结构，支持按 score 排序、按范围查询、按排名访问等。

- **特点**：
  - 多层索引结构，平均 `O(logN)` 搜索
  - 实现简单，性能和内存表现都较好

**与抽象类型的关系：**

- zset：
  - 大型有序集合使用 **skiplist + dict** 组合实现
  - skiplist 负责按照 score 排序和范围查询
  - dict 负责 member -> score 的快速查找

---

## 八、Radix Tree 等有序结构（主要服务于 stream）

从 Redis 5 开始引入的 stream 抽象类型内部使用了有序结构（如压缩前缀树 / Radix Tree）来管理消息 ID 的有序性。

**与抽象类型的关系：**

- stream：
  - 使用有序索引结构按 ID 排序
  - 每个节点内部用 listpack 存储多条消息记录
  - 还会搭配哈希表等结构管理消费组、pending entries 等信息

---

## 九、抽象类型与底层结构的整体映射总结

- **string**：
  - 底层：SDS 或 整数（int 编码）

- **list**：
  - 底层：quicklist（双向链表 + 压缩块）

- **hash**：
  - 小：listpack 编码
  - 大：hashtable（dict）

- **set**：
  - 小且全为整数：intset
  - 一般/大集合：hashtable（dict）

- **zset**：
  - 小：listpack 编码
  - 大：skiplist + dict 组合

- **stream**：
  - 有序索引结构（如 Radix Tree） + listpack + 各种 dict 辅助结构

这些底层结构会根据数据规模、元素特征（是否整数、长度大小等）**自动选择或升级合适的编码**，
从而在空间占用和操作性能之间做平衡。
